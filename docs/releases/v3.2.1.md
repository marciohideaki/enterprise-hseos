# HSEOS v3.2.1 Release Evidence

## Classification and authorization

- **Risk:** High, inherited from the opt-in PostgreSQL migration and control
  plane introduced in v3.2.0; this patch changes only idempotency-key derivation.
- **Breaking changes:** None.
- **Repository-owner acceptance:** correction, publication and installation were
  explicitly authorized in the active delivery session on 2026-09-01.
- **Promotion posture:** GitHub prerelease only; managed enforcement and
  non-loopback exposure remain unavailable.
- **Change record:** [PR #139](https://github.com/marciohideaki/enterprise-hseos/pull/139).

## Root cause and correction

The setup seed used one repository-level idempotency key, while the immutable
command digest also included the authenticated actor. A different authorized
operator therefore presented a different command under an existing key and the
database correctly rejected it. v3.2.1 derives bounded keys from the complete
actor-bound command and preserves explicit caller keys unchanged.

## Verification

- The automated regression fails on v3.2.0 with
  `MANAGED_GOVERNANCE_IDEMPOTENCY_CONFLICT` and passes after the patch.
- Real PostgreSQL setup succeeds for two different operators; the second run
  reports all 276 artifacts unchanged.
- PostgreSQL integration passes 11/11 and the complete governed suite passes.
- CI builds an immutable tarball and CycloneDX SBOM covered by `SHA256SUMS`.

## Rollback

Stop the optional sidecar and reinstall v3.1.1 if managed setup must be removed.
Do not overwrite or delete v3.2.0; it remains immutable release evidence. Keep
the local repository governance authoritative and retain additive database
history.

```bash
rollback_version=3.1.1
rollback_dir="$(mktemp -d)"
gh release download "v${rollback_version}" \
  --repo marciohideaki/enterprise-hseos \
  --dir "${rollback_dir}"
(cd "${rollback_dir}" && sha256sum -c SHA256SUMS)
npm install --global "${rollback_dir}/hseos-${rollback_version}.tgz"
hseos --version
```

Use `sudo` only for an intentionally system-managed, non-writable global npm
prefix. User-managed Node installations must use their owning user.
