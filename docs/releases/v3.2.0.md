# HSEOS v3.2.0 Release Evidence

## Classification and authorization

- **Risk:** High because the opt-in control plane adds an additive PostgreSQL
  migration and infrastructure composition.
- **Breaking changes:** None. Portable repository governance remains
  authoritative and `managed-enforced` remains unavailable.
- **Repository-owner acceptance:** implementation, publication and installation
  were explicitly authorized in the active delivery session on 2026-09-01.
- **Promotion posture:** GitHub prerelease only. No production database profile,
  non-loopback exposure or managed enforcement is authorized.
- **Change record:** [PR #138](https://github.com/marciohideaki/enterprise-hseos/pull/138).

## Artifact and staging

- Tag `v3.2.0` must point to the reviewed release commit on `master`.
- CI must run the complete suite, verify the package surface, build
  `hseos-3.2.0.tgz` and a CycloneDX SBOM, and bind the assets with
  `SHA256SUMS`.
- Staging validation installs the packed artifact in a clean consumer checkout,
  applies the optional client, migrates and seeds an operator-supplied
  PostgreSQL database twice, starts the loopback server and verifies health,
  catalog, authentication and the browser-rendered console.
- Expected staging projection: migration `0004` current and a non-empty catalog.
- Package installation alone must not connect to or mutate PostgreSQL.

## Rollback

Stop the optional sidecar, keep the local repository governance authoritative,
and reinstall the immutable v3.1.1 GitHub asset. The migration is additive; do
not delete audit history or reverse it during package rollback.

```bash
rollback_version=3.1.1
rollback_dir="$(mktemp -d)"
gh release download "v${rollback_version}" \
  --repo marciohideaki/enterprise-hseos \
  --dir "${rollback_dir}"
(cd "${rollback_dir}" && sha256sum -c SHA256SUMS)
npm install --global "${rollback_dir}/hseos-${rollback_version}.tgz"
hseos --version
```

Use `sudo` only when `npm prefix --global` is an intentionally system-managed,
non-writable prefix. User-managed Node installations must use their owning user.

## Post-publication boundary

The GitHub prerelease and local validation do not constitute production
activation. Any production promotion is a separate decision and requires the
high-risk monitoring window and environment-specific database runbook.
