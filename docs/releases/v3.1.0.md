# HSEOS v3.1.0 Release Evidence

> Publication did not complete: the release workflow exposed an intermittent
> SQLite startup lock failure before creating any GitHub release assets. The
> immutable tag is retained for traceability and superseded by v3.1.1.

## Classification and authorization

- **Risk:** High.
- **Reason:** backward-compatible optional feature with additive PostgreSQL
  migrations and new control-plane surfaces.
- **Repository-owner acceptance:** publication and installation explicitly
  authorized in the active delivery session on 2026-09-01.
- **Change reference:** [PR #136](https://github.com/marciohideaki/enterprise-hseos/pull/136).
- **Promotion posture:** GitHub prerelease only. No production database profile,
  non-loopback deployment or managed enforcement is authorized.

## Artifact and staging

- Tag `v3.1.0` must point to the reviewed release commit on `master`.
- CI runs the complete suite, verifies the package surface, builds
  `hseos-3.1.0.tgz` and a CycloneDX SBOM, then binds both with
  asset-relative `SHA256SUMS`.
- CI installs the tarball in a clean directory and exercises the public CLI
  before creating the GitHub prerelease.
- Post-publication staging downloads the exact release assets, verifies
  checksums, installs globally and exercises install-plan, component install,
  control-plane health and console assets.
- PostgreSQL migrations are packaged but never applied by package installation.

## Breaking-change review

No breaking change is introduced. Portable mode remains the default,
repository-owned governance remains authoritative, no built-in profile selects
managed governance and `managed-enforced` remains unavailable.

## Corrected staging findings

- `install-plan` previously resolved capability files from an empty consumer
  working directory instead of the installed HSEOS distribution.
- The managed client was incorrectly listed as two installer modules even
  though its libraries are package-owned runtime assets. Selection now records
  intent without requesting nonexistent module sources.
- The README previously advertised `npx hseos`, but no unscoped `hseos` package
  exists on npm. Installation now uses checksum-verified GitHub assets.

## Rollback

Reinstall the immutable v3.0.3 GitHub asset and disable the optional managed
binding or sidecar. Do not delete audit history or reverse an applied migration.

```bash
rollback_version=3.0.3
rollback_dir="$(mktemp -d)"
gh release download "v${rollback_version}" \
  --repo marciohideaki/enterprise-hseos \
  --dir "${rollback_dir}"
(cd "${rollback_dir}" && sha256sum -c SHA256SUMS)
npm install --global "${rollback_dir}/hseos-${rollback_version}.tgz"
hseos --version
```

## Required evidence before stable or production promotion

- protected CI and release workflow are green with no skipped required gate;
- downloaded checksums and clean tarball installation pass;
- a separately approved PostgreSQL profile proves migration, seed, rollback,
  tenant isolation, backup/restore and operational telemetry;
- a threat model has no critical or high finding open;
- dependent service owners receive the required notice before production;
- staging observation and rollback evidence satisfy the high-risk release gate;
- a separate human decision authorizes any stable promotion or activation.
