# HSEOS v3.4.0 Release Evidence

## Classification and authorization

- **Risk:** Medium. This release adds a policy, a CLI verification mode and
  compiled governance artifacts consumed by product adapters.
- **Breaking changes:** None.
- **Repository-owner acceptance:** implementation, versioning and release
  preparation were explicitly authorized in the active delivery session on
  2026-09-02. Tag creation and global installation remain separate promotion
  actions.
- **Promotion posture:** GitHub prerelease artifact. The capability intake hook
  remains `status: pending` until the final human activation gate.
- **Change record:** [PR #147](https://github.com/marciohideaki/enterprise-hseos/pull/147)
  and [PR #148](https://github.com/marciohideaki/enterprise-hseos/pull/148).

## Capability

This release provides the canonical capability-reuse policy, intake guard and
`capability-check` skill. It also adds `hseos agent-core compile --check`, a
read-only verification mode that fails when compiled agent artifacts or their
canonical sources drift.

The capability graph remains the identity, discovery and ownership authority.
Capability reuse supplies the ordered consume, extend, promote and keep-local
decision process and its enforcement mechanism.

## Verification and rollout

- The handler suite covers eight intake-guard cases.
- `compile --check` covers clean generated output and generated-artifact drift.
- The full enforced quality gate and protected-branch CI must pass before tag
  publication.
- Product consumers must use the checksum-verified GitHub asset to refresh the
  global runtime, then prove `hseos agent-core compile --check` succeeds before
  the pending hook is activated.
- Monitor adapter compilation and capability-drift CI for 30 minutes after
  installation. No production deployment is involved.

## Rollback

Reinstall the checksum-verified v3.3.1 GitHub asset. This removes the additive
`compile --check` command from the runtime but does not mutate project-owned
governance or decision records.

```bash
rollback_version=3.3.1
rollback_dir="$(mktemp -d)"
gh release download "v${rollback_version}" \
  --repo marciohideaki/enterprise-hseos \
  --dir "${rollback_dir}"
(cd "${rollback_dir}" && sha256sum -c SHA256SUMS)
npm install --global "${rollback_dir}/hseos-${rollback_version}.tgz"
hseos --version
```

Use `sudo` only for an intentionally system-managed, non-writable global npm
prefix. User-managed Node installations must use their owning user.
