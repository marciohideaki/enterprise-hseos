# HSEOS v3.0.0 Release Evidence

## Classification and authorization

- **Risk:** High.
- **Reason:** breaking project-state, side-car access, workflow, and capability contracts; first public v3 distribution.
- **Repository-owner acceptance:** explicitly authorized in the active delivery session on 2026-08-31.
- **Production promotion:** not authorized before the 24-hour consumer-notification window and staging validation complete.

## Artifact and staging

- The Git tag must be exactly `v3.0.0` and point at the reviewed release commit.
- The tag workflow builds `hseos-3.0.0.tgz` with `npm pack` and publishes it only as a GitHub prerelease asset.
- `SHA256SUMS` binds the downloadable package and CycloneDX SBOM to the bytes validated by the workflow.
- The workflow installs the tarball in a clean directory and runs the public CLI smoke before creating the GitHub prerelease.
- Post-publication validation downloads the exact release asset, verifies its checksum, installs it in another clean directory, starts the loopback-only state UI side-car, and exercises the rendered UI with a headless browser.

## Consumer notification

`HideakiSolutions/platform-gitops` is the sole installer consumer in the approved G9 registry. This release PR records notification to its repository owner. Production promotion to `latest` must occur no earlier than 24 hours after that notification is recorded.

## Dependency audit

- all production dependencies are pinned exactly in `package.json` and the lockfile is committed;
- `js-yaml` and `yaml` were upgraded to patched compatible releases;
- the direct glob-matching runtime dependency was upgraded to its supported major release, and its transitive dependencies were refreshed;
- `npm audit --omit=dev` reports zero known vulnerabilities;
- the complete production and development tree reports zero known vulnerabilities;
- the deprecated `prebuild-install` package is transitive through `better-sqlite3`; the first driver release that removes it requires Node 22, so maintainers must remove it when the runtime contract can be upgraded without dropping supported Node 20 consumers;
- the release includes a CycloneDX SBOM covered by `SHA256SUMS`;
- the release tarball is regenerated after the lockfile update and must pass the clean-install smoke again.

## Promotion

After staging and browser validation pass, and after the notification window elapses:

```bash
gh release edit v3.0.0 --prerelease=false
```

Promotion must verify the release asset checksum again before changing the prerelease flag.

## Rollback

If staging validation fails, keep the release marked as prerelease and record the failure. If validation fails after promotion, return the release to prerelease and retain the immutable tag and evidence for audit:

```bash
gh release edit v3.0.0 --prerelease
```

Consumers must remain pinned to the previous repository release until a corrected version is published. Git tags and downloaded artifacts are immutable evidence and are never rewritten.

## Required evidence before production

- protected CI and clean-environment smoke are green;
- the downloaded tarball matches `SHA256SUMS`;
- a clean tarball installation runs `hseos --help`;
- the state UI renders successfully in a browser and its health/state requests succeed;
- no browser console error or failed same-origin request is observed;
- the 24-hour consumer-notification window has elapsed;
- the GitHub stable-promotion and rollback commands are reviewed immediately before execution.
