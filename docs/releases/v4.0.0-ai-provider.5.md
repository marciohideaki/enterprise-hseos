# HSEOS 4.0.0-ai-provider.5 — Provider distribution candidate

## Scope and authorization

The repository owner authorized immutable publication, isolated installation and
subsequent product adoption in the active delivery session. This prerelease
distributes the integrated provider discovery and native lifecycle work from
[PR #320](https://github.com/marciohideaki/enterprise-hseos/pull/320), bound to the
published ECP contract bundle and Node/.NET SDK artifact digests.

This is a version 4 candidate rather than a stable promotion of version 3.4.2.
Risk is High relative to the last stable public major version; consumers must
review the [v4 migration guide](../v4-migration.md). The publication stage does not
activate the globally installed runtime or promote any production deployment.
Strategic contract approval and real product adoption remain separately evidenced.

## Artifact boundary

The dedicated manual workflow requires the five protected PR contexts on the
reviewed head and an integrated source commit with exactly the same Git tree.
The frozen compatibility manifest binds the embedded snapshot and each published
dependency's expected digest. The
ordinary preparation PR still runs its complete required CI. The publisher does
not repeat that full suite on an unchanged reviewed tree.

The workflow packs once and stages a draft containing the tarball, CycloneDX SBOM,
compatibility manifest and asset-relative SHA256SUMS. Its clean consumer mounts
only those assets and the probe, installs into a disposable prefix, materializes
the minimal project profile and resolves seven provider discovery surfaces on
Node 22 without a source checkout, global HSEOS, provider credentials or inference.

CI never receives an administration token or private dependency credential. An
external versioned finalizer downloads the published dependency artifacts and
verifies their digests using the separately scoped Gitea package reader, and
checks native immutability for GitHub release dependencies. Reader credentials
are supplied only to the external operator, never CI or the clean consumer.
Gitea exact-version bytes are digest verified; no Gitea WORM claim is made.
It then checks the repository's
native immutable-release setting immediately before publishing
the verified draft, then requires GitHub to attest immutable=true. It never moves
a tag, replaces an asset, changes latest, or rebuilds the sealed package.

## Installation and rollback

Download the release assets and verify SHA256SUMS before installing into a
project-owned prefix. Use the exact tarball covered by those checksums; the
unscoped `hseos` package is not distributed through npm's public registry.

```bash
sha256sum -c SHA256SUMS
npm install --prefix ./hseos-candidate ./hseos-4.0.0-ai-provider.5.tgz
./hseos-candidate/node_modules/.bin/hseos --version
```

Rollback removes the isolated candidate prefix and reinstalls the previous
checksum-verified artifact into that prefix. It does not alter global runtime,
project-owned application data or human bindings. Previously built `.4` candidate
artifacts and the stable v3.4.2 GitHub release remain unchanged.

## Preparation state

external finalizer. The dependency manifest is frozen to the four private Gitea

HSEOS candidate remains unpublished until its own source checks, pack, isolated
installation, draft readback and external immutable finalization complete.
These notes assert no HSEOS publication, deployed adoption or global activation.
