## Decisões

- Vocabulário atual: `not_verified_for_evolution` e `verified_w1..w5_scope_only`.

## Entregas
1. Guard de `deterministic`:
   - o valor tem de ser `not_verified_for_evolution` ou bater com `^verified_w([0-9]+)_scope_only$`, com N entre 0 e 8 (a faixa de ondas do PLAN);
   - qualquer outro valor é recusado.
2. Evidência para valor `verified_*`:
   - se o padrão "valor positivo exige evidência" já está aplicado aos outros eixos, estenda-o com `deterministic_evidence`, uma lista de arquivos que resolvem dentro do checkout, com o mesmo teste de contenção;
   - as famílias que HOJE já têm `verified_wN_scope_only` não podem quebrar. Se elas não têm `deterministic_evidence`, NÃO invente evidência. Nesse caso, o guard exige evidência só para promoções novas, e a lista atual fica registrada como legado aceito, com os IDs fixados no teste para que nenhuma família nova entre sem evidência. Documente a escolha.
