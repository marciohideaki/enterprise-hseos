## Decisões do owner (2026-10-30)

**A2: retry no CI (item 15 do registro W5).** Hoje, falhas de rede do provisionamento só se resolvem com re-run manual. Exemplos: `apt` com HTTP 403 e fetch do chrome-headless-shell.
- Acrescente retry com backoff nas etapas de rede do `.github/workflows/ci.yaml`:
  - `sudo apt-get update` e `install`, no step "Install isolation backend";
  - `node .github/scripts/provision-toolchain-cache.mjs`.
- Use no máximo 3 tentativas com espera crescente, por exemplo 10, 30 e 60 s. Pode ser um laço de shell no próprio `run:` ou retry dentro do script de provisionamento. O script verifica hash e tamanho de cada artefato; o retry **não** pode pular essa verificação: hash divergente continua sendo falha imediata, sem retry.
- Faça o mesmo em outros workflows que tenham o mesmo `apt-get`, como `standalone-smoke.yaml`. Confira.
- Não mude nomes de job nem de check (branch protection). Não mude nenhum gate.
- Teste: em `test/test-ci-light-hook.js`, onde já há asserções sobre o `ci.yaml` (veja o caso do fan-in), afirme que as etapas de rede têm retry. Se o retry ficar no script de provisionamento, escreva um teste unitário do script com download falhando 1x e depois passando, outro com 3 falhas resultando em falha, e outro com hash divergente falhando sem retry.

**A11: aviso de segmento não executado.** O `test:kernel` é uma cadeia `node --test … && npm run … && …`. Quando um segmento falha, os seguintes não rodam, e o relatório do c8 (`test:kernel-coverage`) mostra 0% em massa. Isso parece defeito de cobertura, mas é só segmento não executado; aconteceu em 2026-10-30.
- Ao reportar falha de um item, o runner da suíte (`.github/scripts/ci-test-shards.mjs` e/ou `suite-orphans.mjs`) passa a listar quais segmentos da cadeia `&&` do item chegaram a rodar e quais não rodaram. Existe `segmentsOf` em `suite-orphans.mjs:~130`; reutilize. Quando o item for `npm run test:kernel-coverage`, acrescente uma linha explícita: "a cobertura de arquivos exercitados só pelos segmentos não executados aparece como 0% e não indica falta de teste".
- **Nada de gate muda:** o exit code do item e da suíte é o mesmo, os limiares são os mesmos e a supervisão de órfãos é a mesma. É só mensagem.
- Teste em `test/test-ci-light-hook.js`: um item com cadeia `a && b && c` em que `b` falha. A saída lista `a` como executado e `b` como falho, `c` aparece como não executado, e o exit code continua o de falha. Para o caso `test:kernel-coverage`, afirme a linha explicativa.
