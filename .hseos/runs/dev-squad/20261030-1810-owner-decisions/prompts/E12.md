## Defeito
O timer systemd `hseos-liveness-watch` roda a cada ciclo:

```
node <release>/tools/cli/hseos-cli.js liveness watch --once --directory /workspace/github/marciohideaki/enterprise-hseos
```

Desde a ativação do `project.db` (ADR-0048, 2026-10-22, schema v4 → v17), ele falha sempre com `EXECUTION_ACTIVATION_PENDING`:

> Operational state requires schema v4; pending execution schema is not activated. If this database was activated, this legacy server cannot open it…

A mensagem vem de `assertOperationalSchemaBoundary` (`tools/mcp-project-state/lib/operational-state-db.js:~31`). O caminho de escrita de `openLivenessDb` (`tools/lib/agent-liveness.js:~218`) chama `openOperationalStateDatabase(dbPath)`, o abridor legado/v4, que recusa um banco ativado.

## Antes de corrigir
- Descubra como os servidores MCP modernos, que já servem o banco ativado, o abrem. Veja os serviços `hseos-project-state` (`tools/mcp-project-state/index.js`, modo moderno) e as funções de `operational-state-db.js` para banco ativado: `classifyExecutionActivation` e o abridor governado/ativado.
- Reutilize esse abridor; não reimplemente.
- O banco ativado continua tendo a tabela `as_liveness_events`? Se o schema ativado não a tiver, ou se `ensureLivenessSchema` precisar criar a tabela num banco ativado, descubra se isso é permitido pelo ADR-0048. Lá, criar tabela num banco ativado fora de migração é suspeito. Se não for permitido, reporte BLOCKED com o motivo, sem contornar.
- Reproduza o defeito com um banco ativado em fixture descartável, pelo mesmo caminho de fixture que `test/test-execution-ledger-activation.js` usa. Vermelho primeiro: `liveness watch --once` falha com `EXECUTION_ACTIVATION_PENDING`.

## Entregas
1. `openLivenessDb`, na escrita, abre o banco ativado pelo abridor moderno, sem afrouxar a fronteira:
   - banco v4 legado: continua abrindo como hoje;
   - banco ativado: abre pelo caminho moderno;
   - banco em estado intermediário ou sem critério de ativação: continua recusando.
   Na leitura (`readonly`), confira se há o mesmo problema.
2. Testes:
   - banco ativado em fixture → `liveness watch --once` / `recordEvent` funciona;
   - banco v4 continua funcionando;
   - banco pendente ou inválido continua recusado com o código atual.
   - Mutação descartável: forçar o abridor legado derruba o teste novo.
3. Se o comando ou a unidade gerada (`liveness` install/timer) precisar de mudança para o banco ativado, inclua. Não edite unidades em `~/.config/systemd`: isso é do Commander, na janela A12.
4. Docs: `docs/evolution/runbooks/activation.md` ou o runbook do liveness, se citar o watchdog.
