## Defeito (achado pelo Commander no CI da PR #262, job 124426311390, Node 24, shard 5/6)
O teste `test/test-install-lock.js:444` ("two installers in one process racing for the same directory: one is accepted, the other refused") falhou com `a.status` `'fulfilled'` quando se esperava `'rejected'`.

A causa é o teste, não o lock:
- `release()` roda de forma síncrona dentro do `Promise.allSettled`, antes que o segundo `_withInstallLock` tente `createLockFile`.
- Os dois passam por `ensureDir` e `writeFile`, que são assíncronos.
- Se o primeiro adquirir, terminar o `work` (o gate já liberado) e soltar o lock antes da primeira tentativa do segundo, o segundo é aceito legitimamente.

O código do lock (`tools/cli/installers/lib/core/installer.js:309-350`) NÃO deve ser alterado.
